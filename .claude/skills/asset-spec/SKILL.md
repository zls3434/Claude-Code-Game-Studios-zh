## 阶段 0b：实体与界面清单（在没有参数且没有现有清单时运行）

此流程生成 `design/assets/entity-inventory.md` — 游戏所需的一切视觉内容的完整清单。在资产规格工作开始之前运行一次。

### 步骤 1 — 从文档中收集
并行读取所有可用的源材料：
- `design/gdd/systems-index.md` — 提取列出的每个系统
- `design/gdd/` 中的所有 GDD — 提取：视觉/音频需求部分、提到的 UI 元素、VFX 事件、任何命名实体（角色、敌人、建筑、物品）
- `design/art/art-bible.md` — 提取：任何命名的视觉类别、资产类型预期
- `design/narrative/` — 扫描任何角色或世界实体文档（如果存在 — 可选，非必需）

### 步骤 2 — 构建建议清单
将找到的所有内容组织到以下类别中：

```
角色 / 主角
敌人 / 生物
建筑 / 结构
环境 / 地形
物品 / 道具
VFX / 粒子
UI 界面（按名称列出每个界面）
HUD 元素
音频（音效、音乐 — 仅描述，不生成 Prompt）
其他
```

对于每个项目，注明发现它的源文档。

### 步骤 3 — 呈现与协作
在对话中将完整的建议清单呈现给用户。然后使用 `AskUserQuestion`：
- 提示："我在您的 GDD 和美术圣经中找到了 **[N] 个视觉实体和 [N] 个 UI 界面**。审查清单 — 缺少什么、什么不需要？"
- 选项：
  - `[A] 看起来不错 — 保存此清单`
  - `[B] 添加我将描述的项目`
  - `[C] 移除不适用的项目`
  - `[D] 既添加又移除 — 让我编辑`

如果 [B] 或 [D]：请用户描述额外的项目。接受简短描述（"一座中世纪要塞，用作关卡背景"）或详细描述 — 都可以。协作处理直到用户满意。

如果 [C] 或 [D]：询问要移除哪些项目及其原因。从清单中移除它们。

### 步骤 4 — 写入清单
用户批准后，询问："可以将实体清单写入 `design/assets/entity-inventory.md` 吗？"

写入文件：

```markdown
# 视觉实体与界面清单

> 生成日期：[日期]
> 数据源：[已读取的源文档列表]

## 实体

| # | 名称 | 类型 | 描述 | 数据源 | 状态 |
|---|------|------|------|--------|------|
| 1 | [名称] | 角色 / 敌人 / 建筑 / 环境 / 物品 / 其他 | [简要描述] | [源文档] | 需要（Needed） |

## UI 界面

| # | 界面名称 | 描述 | 数据源 | 状态 |
|---|---------|------|--------|------|
| 1 | 主菜单 | [描述] | [数据源] | 需要（Needed） |

## HUD 元素

| # | 元素 | 描述 | 数据源 | 状态 |
|---|------|------|--------|------|

## 音频

| # | 名称 | 类型（音效 / 音乐 / 环境音） | 描述 | 数据源 | 状态 |
|---|------|------------------------------|------|--------|------|
```

写入后，告诉用户：
> "实体清单已保存。后续步骤：
> - 对清单中的每个 UI 界面运行 `/ux-design [界面名称]`
> - 运行 `/asset-spec entity:[名称]` 为每个视觉实体生成规格
> - 或再次运行 `/asset-spec` 逐一处理清单中的项目"

## 阶段 0：解析参数

提取：
- **目标类型**：`system`、`level` 或 `character`
- **目标名称**：冒号后的名称（规范化为 kebab-case）
- **审核模式**：`--review [full|lean|solo]`（如果存在）

**模式行为：**
- `full`（默认）：并行 spawn `art-director` 和 `technical-artist`
- `lean`：仅 spawn `art-director` — 更快，跳过技术约束环节
- `solo`：不 spawn 任何代理 — 主会话仅根据美术圣经规则编写规格。适用于简单资产类别或速度优先于深度的情况。

---

## 阶段 1：收集上下文

在向用户询问任何内容**之前**，读取所有源材料。

### 必需读取：
- **美术圣经**：读取 `design/art/art-bible.md` — 如果缺失则失败：
  > "未找到美术圣经。请先运行 `/art-bible` — 资产规格以美术圣经的视觉规则和资产标准为基础。"
  提取：视觉身份声明、颜色系统（语义颜色）、形状语言、资产标准（第 8 节 — 尺寸、格式、面数预算、纹理分辨率层级）。

- **技术偏好**：读取 `.claude/docs/technical-preferences.md` — 提取性能预算和命名规范。

### 按目标类型的源文档读取：
- **system**：读取 `design/gdd/[目标名称].md`。提取**视觉/音频需求**部分。如果它不存在或内容是 `[待设计]`：
  > "`design/gdd/[目标名称].md` 的视觉/音频部分是空的。要么运行 `/design-system [目标名称]` 完成 GDD，要么手动描述视觉需求。"
  使用 `AskUserQuestion`：`[A] 手动描述需求` / `[B] 停止 — 先完成 GDD`
- **level**：读取 `design/levels/[目标名称].md`。提取美术需求、资产列表、VFX 需求以及步骤 4 中美术指导的制作概念规格。
- **character** 或 **entity**：读取 `design/narrative/characters/[目标名称].md` 或在 `design/narrative/` 和 `design/assets/entity-inventory.md` 中搜索匹配条目。提取视觉描述、角色和任何指定的区分特征。
  - **如果没有源文档存在**：不要失败。而是使用 `AskUserQuestion`：
    - 提示："未找到 **[名称]** 的设定文档。简要描述一下 — 一两句话就够了。"
    - 选项：`[A] 现在描述它` / `[B] 跳过此实体` / `[C] 到此为止`
    - 如果 [A]：用户的描述成为数据源。简短回答生成简洁规格；详细回答生成详细规格。接受用户提供的任何详细程度并以此为基础。

### 可选读取：
- **现有清单**：读取 `design/assets/asset-manifest.md`（如果存在）— 提取此目标已有规格的资产以避免重复。
- **相关规格**：Glob `design/assets/specs/*.md` — 扫描可以共享的资产（例如，为一个系统生成的通用 UI 元素可能也适用于此处）。

### 呈现上下文摘要：
> **资产规格：[目标类型] — [目标名称]**
> - 源文档：[路径] — 识别到 [N] 种资产类型
> - 美术圣经：已找到 — 资产标准见第 8 节
> - 此目标的现有规格：[N 个已有规格 / 无]
> - 在其他规格中找到的共享资产：[列表或"无"]

## 阶段 2：资产识别

从源文档中提取每种提及的资产类型 — 显式的和隐含的。

**对于系统**：查找 VFX 事件、精灵引用、UI 元素、音频触发器、粒子效果、图标需求以及任何"视觉反馈"语言。

**对于关卡**：查找独特的场景道具、大气 VFX、光照设置、环境音效、天空盒/背景以及任何特定区域的材质。

**对于角色**：查找精灵表（待机、行走、攻击、死亡）、头像/肖像、附着于技能的 VFX、UI 表现（图标、血条皮肤）。

将资产分组为以下类别：
- **精灵 / 2D 美术** — 角色精灵、UI 图标、图块表
- **VFX / 粒子** — 打击效果、环境粒子、屏幕效果
- **环境** — 道具、图块、背景、天空盒
- **UI** — HUD 元素、菜单美术、字体（如果是自定义的）
- **音频** — 音效、音乐轨道、环境音循环 *（注意：音频规格仅为描述 — 不生成 AI Prompt）*
- **3D 资产** — 网格、材质（如果引擎适用）

向用户呈现完整的已识别清单。使用 `AskUserQuestion`：
- 提示："我为 **[目标]** 识别到 [N] 个资产，分布在 [N] 个类别中。生成规格前审查："
- 先在对话文本中显示分组清单
- 选项：`[A] 继续 — 为所有这些生成规格` / `[B] 移除一些资产` / `[C] 添加我漏掉的资产` / `[D] 调整类别`

在用户确认资产列表之前，不要进入阶段 3。

---

## 阶段 3：规格生成

根据审核模式 spawn 专家代理。**同时发出所有 Task 调用 — 不要等待一个完成再开始下一个。**

### Full 模式 — 并行 spawn：

**`art-director`** 通过 Task：
- 提供：阶段 2 的完整资产列表、美术圣经的视觉身份声明、颜色系统、形状语言、源文档的视觉需求以及美术圣经第 9 节中提到的任何参考游戏/美术
- 要求："对于此列表中的每个资产，生成：(1) 一个 2–3 句的视觉描述，锚定于美术圣经的形状语言和颜色系统 — 具体到两个不同的艺术家会产生一致的结果；(2) 一个即用型的 AI 图像生成 Prompt（Midjourney/Stable Diffusion 风格 — 包含风格关键词、构图、调色板锚点、负面提示词）；(3) 哪些美术圣经规则直接管辖此资产（按节引用）。对于音频资产，描述其声音特征而非生成 Prompt。"

**`technical-artist`** 通过 Task：
- 提供：完整资产列表、美术圣经资产标准（第 8 节）、technical-preferences.md 性能预算、引擎名称和版本
- 要求："对于此列表中的每个资产，指定：(1) 精确的尺寸或面数（匹配美术圣经资产标准层级 — 不要发明新尺寸）；(2) 文件格式和导出设置；(3) 命名规范（来自 technical-preferences.md）；(4) 此资产类型必须遵守的任何引擎特定约束；(5) LOD 要求（如适用）。标记美术圣经首选标准与引擎约束存在冲突的任何资产类型。"

### Lean 模式 — 仅 spawn art-director（跳过 technical-artist）。

### Solo 模式 — 两者都跳过。仅从美术圣经规则推导规格，注明技术约束未被验证。

**在阶段 4 之前收集两个响应。** 如果 art-director 和 technical-artist 之间存在任何冲突（例如，art-director 指定 4K 纹理但 technical-artist 标记引擎预算要求 512px），明确展示 — 不要静默解决。

---

## 阶段 4：编译和审核

将代理输出整合为每个资产的规格草案。使用此格式在对话文本中呈现所有规格：

```
## ASSET-[NNN] — [资产名称]

| 字段 | 值 |
|-------|-------|
| 类别 | [精灵 / VFX / 环境 / UI / 音频 / 3D] |
| 尺寸 | [例如 256×256px，4 帧精灵表] |
| 格式 | [PNG / SVG / WAV / 等] |
| 命名 | [例如 vfx_frost_hit_01.png] |
| 面数 | [如果是 3D — 例如 <800 tris] |
| 纹理分辨率 | [例如 512px — 匹配美术圣经 §8 层级 2] |

**视觉描述：**
[2–3 句。具体到两个不同的艺术家会产生一致的结果。]

**美术圣经锚点：**
- §3 形状语言：[应用的相关规则]
- §4 颜色系统：[颜色角色 — 例如"根据语义颜色规则使用威胁蓝"]

**生成 Prompt：**
[即用型 Prompt。包含：风格关键词、构图说明、调色板锚点、光照方向、负面提示词。]

**状态：** 需要（Needed）
```

呈现所有规格后，使用 `AskUserQuestion`：
- 提示："**[目标]** 的资产规格 — [N] 个资产。审查完成？"
- 选项：`[A] 全部批准 — 写入文件` / `[B] 修改特定资产` / `[C] 以不同方向重新生成`

如果 [B]：询问哪个资产以及要更改什么。内联修改并重新呈现。不要为轻微文本修改重新 spawn 代理 — 只有在视觉方向本身需要改变时才重新 spawn。

如果 [C]：询问要改变什么方向。用更新的简报重新 spawn 相关代理。

---

## 阶段 5：写入规格文件

批准后，询问："可以将规格写入 `design/assets/specs/[目标名称]-assets.md` 吗？"

写入文件，包含：

```markdown
# 资产规格 — [目标类型]：[目标名称]

> **数据源**：[源 GDD/关卡/角色文档的路径]
> **美术圣经**：design/art/art-bible.md
> **生成日期**：[日期]
> **状态**：[N] 个资产已生成规格 / [N] 个已批准 / [N] 个生产中 / [N] 个已完成

[所有以 ASSET-NNN 格式的资产规格]
```

然后更新 `design/assets/asset-manifest.md`。如果它不存在，创建它：

```markdown
# 资产清单

> 最后更新：[日期]

## 进度摘要

| 总计 | 需要（Needed） | 进行中 | 已完成 | 已批准 |
|------|--------|-------|------|------|
| [N] | [N] | [N] | [N] | [N] |

## 按上下文分类的资产

### [目标类型]：[目标名称]
| 资产 ID | 名称 | 类别 | 状态 | 规格文件 |
|----------|------|------|------|----------|
| ASSET-001 | [名称] | [类别] | 需要（Needed） | design/assets/specs/[目标]-assets.md |
```

如果清单已存在，追加新的上下文块并更新进度摘要计数。

询问："可以更新 `design/assets/asset-manifest.md` 吗？"

## 阶段 6：结束

使用 `AskUserQuestion`：
- 提示："**[目标]** 的资产规格已完成。下一步是什么？"
- 选项：
  - `[A] 为另一个系统生成规格 — /asset-spec system:[下一个系统]`
  - `[B] 为关卡生成规格 — /asset-spec level:[关卡名称]`
  - `[C] 为角色生成规格 — /asset-spec character:[角色名称]`
  - `[D] 运行 /asset-audit — 对照规格验证已交付的资产`
  - `[E] 到此为止`

## 资产 ID 分配

资产 ID 在整个项目中按顺序分配 — 不是按上下文的。在分配 ID 之前读取清单以查找当前的最大编号：

```
Grep pattern="ASSET-" path="design/assets/asset-manifest.md"
```

从 `ASSET-[最大编号 + 1]` 开始新资产。这确保 ID 在整个项目中是稳定且唯一的。

如果还没有清单，从 `ASSET-001` 开始。

---

## 共享资产协议

在为资产生成规格之前，检查其他上下文的规格中是否已存在等效资产：

- 通用 UI 元素（血条、分数显示）通常在系统间共享
- 通用环境道具可能出现在多个关卡中
- 角色 VFX（打击火花、死亡效果）可能复用基础规格并仅更改颜色变体

如果找到匹配：引用现有的 ASSET-ID 而不是创建重复项。在清单的"被引用者"列中注明共享使用。

> "ASSET-012（通用打击火花）已为战斗系统生成规格。在塔防中复用 — 将塔防添加到被引用者。"

---

## 错误恢复协议

如果任何 spawn 的代理返回 BLOCKED 或无法完成：

1. 立即展示："[代理名称]：已阻塞 — [原因]"
2. 在 `lean` 模式下或如果 `technical-artist` 阻塞：仅使用 art-director 的输出继续 — 注明技术约束未被验证
3. 在 `solo` 模式下或如果 `art-director` 阻塞：从美术圣经规则推导描述 — 标记"美术指导未咨询 — 在生产前对照美术圣经验证"
4. 始终生成部分规格 — 绝不要因为一个代理阻塞就丢弃已完成的工作

---

## 协作协议

每个阶段遵循：**识别 → 确认 → 生成 → 审核 → 批准 → 写入**

- 绝不要在与用户确认资产列表之前就为资产生成规格
- 始终将规格锚定于美术圣经 — 与美术圣经矛盾的规格是错误的
- 展示所有代理分歧 — 不要静默选择其中一方
- 仅在明确批准后才写入规格文件
- 写入规格后立即更新清单

## 推荐的后续步骤

- 运行 `/asset-spec [下一个上下文]` 继续为剩余的系统、关卡或角色生成规格
- 运行 `/asset-audit` 对照已写的规格验证已交付的资产，并识别差距或不匹配
