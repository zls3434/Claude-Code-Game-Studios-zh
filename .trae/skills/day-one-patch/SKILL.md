# 发布日补丁

本 Skill 在最终发布候选版已标记后运行，且必须运行在 `/release-checklist` 之后。它是从"功能冻结"到"出门发布"之间所需修复的集中清单。

**何时运行：** 在发布候选版已标记之后，距离发布 1–7 天。

**关联 Skill：** `/release-checklist`（先运行）、`/changelog [版本号]`（运行以提供背景）、`/hotfix`（如果发现问题）。

**输出：** `production/qa/day-one-patch-[date].md`

---

## 阶段 1：加载背景

运行 `git log --oneline [last-tag]..[release-candidate-tag]` 获取此版本的所有提交。

Glob 并读取 `production/qa/launch-review-*.md`（最新）以获取尚未通过 `/release-checklist` 处理的已知问题。

---

## 阶段 2：快速审计

审核发布候选版是否具备发布就绪性，不再有功能变更，仅修复。

### 版本号
- 构建中的显示版本是否与计划版本一致？
- 标记的提交是否为构建提交？（检查 `git tag -l '[version]*'`）

### 崩溃日志
- 安装 `adb logcat` / Xcode Organizer / crash 报告
- 是否有任何崩溃频率高于 1 次/千次会话？
- 是否有任何崩溃在发布候选版中是新的？

### 性能
- 在最低规格设备上测量加载时间
- 检查每关/每区域/每屏幕的帧时间（>30ms 为红色）
- 发布构建中的内存是否在预算内？

### 资产完整性
- 是否有任何资产引用失败？（缺失纹理、缺失声音）
- 关卡是否加载完成？（无回退/占位符）
- 检查是否存在缺失的本地化（Grep 搜索 `MISSING_TRANSLATION` 或占位符字符串）

### 发布候选版标记以来的提交
- 自发布候选版标记以来是否已有提交？
- 如果有：手动列出每条提交。将其分类为：
  - **错误——不该在发布候选中包含**：重构、新功能、触及与修复无关文件的格式变更
  - **必要修复**：崩溃修复、值修正——是发布日补丁的有效候选
  - **不清楚**：提交信息不清晰，无法自信分类
- 如果存在任何"错误"类别的提交，以粗体黄色标注：
  > "⚠️ 自发布候选版 [tag] 以来检测到 [N] 次非修复提交。发布候选版应该是冻结的——仅允许修复。这些提交引入了不必要的风险，需要人工审查。是否应将其回退？"

---

## 阶段 3：发布日补丁项目

列出**仅阻塞性**项目——离开它们会损害玩家体验的问题。

对于每个项目：
- 严重程度：发布阻塞 / 强烈建议 / 如果时间允许
- 影响区域
- 修复估计（行数/小时）
- 风险（修复造成回归的可能性）

按优先级排序，并将发布阻塞项标记为 **阻塞发布**。

---

## 阶段 4：不修复项

审查 `/release-checklist` 输出中的每个未解决项目。对于每个可接受不修复的项目，
记录理由：它是否会降低体验？是否会损害评论分数？如果修复它可能会破坏什么？

---

## 阶段 5：发布日补丁计划

生成带有具体任务分配的集中补丁计划：

```markdown
# 发布日补丁：[版本号]
日期：[日期]
发布候选版：[标签]

## 快速审计结果
- 崩溃： [干净 / N 个高于阈值的崩溃]
- 性能： [干净 / 检测到问题]
- 资产： [干净 / 发现问题]
- 本地化： [完整 / 缺失键值]

## 自发布候选版以来的提交
[提交日志，或 "无 —— 自发布候选版标记以来构建是干净的"]

## 发布日补丁项目（按严重程度排序）

### 发布阻塞项
- **[项目]**：[描述、修复、风险]
  负责人： [是谁]
  预计时间： [X 小时]
  风险： [低/中/高]

### 强烈建议
- **[项目]**：...

### 如果时间允许
...

## 不修复项（风险已接受）
[列表含理由]

## 补丁时间线
- [日期] [时间]：开始修复
- [日期] [时间]：补丁中的首批修复可用于 QA
- [日期] [时间]：补丁版本标记

## 发布日状态
状态： [就绪 / 存在风险 / 受阻]
```

---

## 阶段 6：Gate 和写入

在对话中呈现补丁计划，然后询问：

> "我可以将发布日补丁写入 `production/qa/day-one-patch-[date].md` 吗？"

仅在审批后写入。然后：

- 如果存在 S1/S2 崩溃： "S1 崩溃必须在构建出门之前修复。运行 `/hotfix` 追踪这些修复。"
- 如果 GPU 崩溃且只有高端设备："考虑在不受支持的硬件上禁止运行——在引擎设置中对低端设备进行性能分级。"
- 如果发布阻塞项完全取消："所有发布阻塞项已解决。可以出门。"

判定：**完成** —— 发布日补丁已生成 / **受阻** —— 存在 S1/S2 崩溃
