# Agent Test Spec：economy-designer

## Agent 摘要
- **领域**：资源经济设计、掉落表设计、进度曲线（XP、等级、解锁）、游戏内市场和商店设计、经济平衡分析、产出和消耗机制、通胀/通缩风险评估
- **不拥有**：Live ops 事件排期和结构（live-ops-designer）、代码实现、分析追踪设计（analytics-engineer）、经济系统的叙事论证（writer）
- **Model tier**：Sonnet
- **Gate ID**：无；将破坏经济的设计冲突升级到 creative-director 或 producer

---

## 静态断言（结构性）

- [ ] `description:` 字段存在且领域特定（引用经济、掉落表、进度曲线、平衡）
- [ ] `allowed-tools:` 列表匹配 agent 角色（Read/Write 用于 design/balance/ 文档；无代码或分析工具）
- [ ] Model tier 为 Sonnet（design specialist 默认）
- [ ] Agent 定义不声称对 live ops 排期、代码或叙事拥有权限

## 测试用例

### Case 1：域内请求 — 宝箱掉落表设计
**输入**："为我们地牢游戏设计标准宝箱的掉落表。"
**预期行为**：
- 产出包含不同稀有度层级的概率表：Common、Uncommon、Rare、Epic、Legendary（或项目等效层级）
- 每个层级有：概率百分比、示例物品类别、以及预期金币等价物价值范围
- 概率之和为 100%
- 包含每个层级概率的简短理由：为什么 Common 设为其值，为什么 Legendary 设为其值
- 不产出单一扁平物品列表 — 使用分层概率结构以体现有意义的稀有度

### Case 2：领域外请求 — 季节性事件排期
**输入**："设计我们的夏季事件和秋季事件的排期。何时运行以及每个应持续多长时间？"
**预期行为**：
- 不产出事件排期或内容节奏计划
- 明确声明："Live ops 事件排期由 live-ops-designer 拥有；我设计事件结构中奖励的经济结构，一旦事件排期确定"
- 提供一旦 live-ops-designer 定义结构后产出奖励价值设计

### Case 3：领域边界 — 新货币的通胀风险
**输入**："我们正在添加一种新的'声望币'货币，通过完成所有季节性内容获得。玩家可以在声望商店消费。"
**预期行为**：
- 识别通胀风险：如果声望币积累速度快于商店提供消耗渠道，商店失去感知价值，玩家囤积货币而不消费
- 标记具体风险：季节性内容完成是有限产出，但如果商店目录在季节结束前耗尽，季末币种无价值
- 提出消耗机制：轮换限时商店物品、声望商店中的消耗品物品、或货币兑换选项以保持货币消耗
- 不批准设计为经济上健全而不解决消耗问题
- 产出结构化风险评估：产出率（估计币/周）、消耗容量（耗尽目录所需估计币数）、盈余预测

### Case 4：中期进度曲线问题
**输入**："玩家报告中期 XP 磨练（等级 20-35）感觉像一堵墙。每级需要 3 倍 XP 但奖励不按比例增加。"
**预期行为**：
- 识别此为进度曲线问题：XP 成本增长率超过奖励增长率
- 产出修订后的 XP 公式或曲线调整：要么降低等级 20-35 的 XP 成本乘数，增加该范围的奖励 XP，或引入追赶机制（完成显著低于玩家等级内容时获得额外 XP）
- 展示数学：当前曲线 vs. 提出的曲线，附上等级 20、25、30、35 的具体数字
- 标记任何曲线变更影响到达等级上限的时间预测 — 注明对终局内容节奏的下游影响

### Case 5：上下文传递 — 使用当前经济数据进行平衡分析
**输入上下文**：当前经济数据：玩家平均每小时赚取 450 金币，平均商店物品成本 2,000 金币，平均会话长度 40 分钟。高级物品成本 5,000 金币。
**输入**："我们当前的金币经济健康吗？是否应调整价格或赚取率？"
**预期行为**：
- 使用提供的具体数字：450 金币/小时 = 300 金币/40 分钟会话；2,000 金币物品需要约 4.4 次会话才可购买；5,000 金币高级物品需要约 11 次会话
- 根据经济设计原则评估这些比率是感觉有奖励还是令人沮丧
- 使用实际数字产出具体建议：例如"在当前赚取率下，高级物品需约 7.3 小时游玩才可购买 — 这在可接受范围的高端；考虑要么将赚取率提高到 550 金币/小时，要么将高级物品成本降低到 4,000 金币"
- 不由锚定于提供的数据而产出泛化建议（"价格可能太高"）

## 协议合规性

- [ ] 停留在声明领域内（掉落表、进度曲线、资源经济、通胀/通缩分析）
- [ ] 将 live ops 排期请求重定向到 live-ops-designer 而不产出行程表
- [ ] 通过量化的消耗/产出分析主动标记通胀/通缩风险
- [ ] 为进度曲线产出明确的数学 — 无数字的模糊曲线调整
- [ ] 使用上下文中的实际经济数据；当提供具体数据时不产生泛化基准

---

## 覆盖说明
- Case 3（通胀风险）是经济健康测试 — 错过的通胀风险在 live 游戏中造成长期经济损害
- Case 4 要求 agent 产出实际数字，而非曲线形状 — 验证数学存在，而非仅叙述
- Case 5 是最重要的上下文感知测试；agent 必须使用提供的数据，而非占位值
- 无自动化运行器；手动审查或通过 `/skill-test`
