# Agent Test Spec：qa-tester

## Agent 摘要
- **领域**：测试执行、bug 复现、测试用例编写、测试证据收集、回归测试运行
- **不拥有**：QA 策略（qa-lead）、bug 修复（适当程序员）、安全测试（security-engineer）
- **Model tier**：Sonnet
- **Gate ID**：无；将策略决策升级到 qa-lead

---

## 静态断言（结构性）

- [ ] `description:` 字段存在且领域特定（引用测试执行、bug 复现、测试用例编写）
- [ ] `allowed-tools:` 列表匹配 agent 角色（读取代码但仅用于识别测试目标；写入 test_evidence 文件；如项目信息需要则包含 Bash）
- [ ] Model tier 为 Sonnet（specialist 默认）
- [ ] Agent 定义不声称对 QA 策略、bug 修复或安全测试拥有权限

## 测试用例

### Case 1：域内请求 — 编写测试用例
**输入**："我们的背包系统需要单元测试。仅"添加物品"操作 — 编写测试用例。"
**预期行为**：
- 产出结构化测试用例，格式匹配项目的测试标准（由 coding-standards.md 指定：unit, integration, visual, UI）
- 测试用例应清晰明确：提供输入物品、预期的背包状态、预期返回值/错误
- 包含正常情况、空背包边缘情况、满背包边缘情况、堆叠物品变体以及至少一个重叠/边界情况（例如添加最后一个物品到满背包并再添加一个）
- 不写出实际的单元测试代码（这属于 gameplay-programmer）— 仅测试用例

### Case 2：领域外请求 — bug 修复
**输入**："我在背包测试中发现了这个 bug。你能修复它吗？"
**预期行为**：
- 不修复 bug
- 产出结构化的 bug 报告（而非补丁）：明确标题、预期行为、实际行为、复现步骤、严重性、可能影响的系统
- 将 bug 路由到适当的程序员

### Case 3：回归测试运行
**输入**："我们刚刚更改了背包排序算法。运行背包回归套件。"
**预期行为**：
- 列出应按优先级运行的背包回归测试用例，在适用时引用现有的测试文件或测试规范
- 如果存在，运行实际测试（通过 Bash 命令），并报告期望结果和实际结果
- 如果测试失败，产出结构化的失败报告，区分重复性问题和新 bug

### Case 4：测试证据 — 视觉质量检查
**输入**："新的物品图标有一些看起来像素化。收集视觉证据。"
**预期行为**：
- 产出视觉证据收集检查清单：屏幕截图或录制用于检查物品图标是否正确以目标分辨率呈现，在放大状态下，存在重采样伪影、透明度伪影或阴影伪影时使用比较示例
- 不产出代码修复 — 仅报告视觉问题是什么以及如何在何处验证

### Case 5：上下文传递 — 使用特定测试标准
**输入上下文**：coding-standards.md 规定：Logic story 需要阻塞式自动化单元测试，Visual story 需要对比截图，UI story 需要交互日志，Data/Config 需要冒烟检查。
**输入**："我们正在测试一个 Logic 类型的 story。我们有哪些测试证据要求？"
**预期行为**：
- 引用提供的上下文：Logic story → 阻塞式自动化单元测试
- 产出适合 Logic story 的具体测试要求：需要测试文件、需要测试通过状态，可能还需要所需的测试覆盖率百分比
- 不因建议而应用 Visual story 或 Data/Config 标准
- 产出检查清单以确保所有要求的证据类型均已收集，然后才报告准备就绪

## 协议合规性

- [ ] 停留在声明领域内（测试编写/执行、bug 报告、证据收集）
- [ ] 将 bug 报告路由到适当程序员 — 严禁静默修复
- [ ] 为自动化测试使用项目的测试框架和命名约定
- [ ] 将策略决策（测试框架、覆盖标准、优先级）升级到 qa-lead
- [ ] 根据提供的上下文中的 story 类型应用正确的测试标准

---

## 覆盖说明
- Case 1（测试用例）应匹配 coding-standards.md 中的项目格式；如果格式不匹配则失败
- Case 5（上下文传递）是最重要的上下文感知测试 — agent 必须正确分类 story 标准
- 回归测试运行需要现有测试文件（可能不存在）
- 无自动化运行器；手动审查或通过 `/skill-test`
